# Buffet Restaurant Sim

Godot 4 自助餐经营模拟项目。当前已经从纯灰盒进入第一套垂直切片，但仍坚持：玩法逻辑不为美术让路，美术也不反向污染底层接口。

## 当前版本：v0.7 第一套垂直切片

### 第一套正式场景素材已经接入

当前已加入并实际引用：

- 餐厅地板
- 后墙
- 收银台
- 后厨工作台
- 厕所入口
- 标准自助餐台
- 双人桌
- 餐盘
- 普通顾客
- 厨师
- 服务员

资源统一放在：

assets/vertical_slice/

当前使用简单 SVG 作为第一版垂直切片母版。原因不是把 SVG 当最终美术，而是先验证比例、脚底锚点、透视、遮挡和动作接口。正式精修 PNG 后续可以直接替换纹理，不需要重写顾客、员工和经营系统。

### 人物动画结构

三类人物已经统一使用：

scripts/actor_visual.gd

当前动作接口包括：

- 行走
- 待机
- 端盘
- 夹菜
- 吃饭
- 收盘
- 擦桌
- 厨师制作
- 厨师补菜

方向处理：

- 前向两帧走路
- 后向两帧走路
- 左右方向通过镜像得到
- 因此逻辑上已经覆盖 NW / NE / SW / SE 四方向
- 后续如果美术需要更强方向差异，可以直接换成四套独立帧，不动角色状态机

Godot 的 AnimatedSprite2D + SpriteFrames 负责基础逐帧动画，ActorVisual 统一负责方向、动作姿态、端盘显示和轻量动作反馈。

### 顾客视觉

顾客不再是彩色色块。

当前：

付款取盘 → 显示餐盘 → 排餐台 → 夹菜动作 → 端盘回桌 → 吃饭姿态 → 离店收盘。

不同顾客类型仍保留一个小型颜色标记用于灰盒阶段识别，正式人物批量扩展后可移除。

### 厨师视觉

厨师现在拥有正式人物母版并继续执行真实任务：

接任务 → 去后厨 → 制作 → 端菜 → 走到目标餐台 → 补菜。

端菜状态会显示餐盘/托盘视觉。

### 服务员视觉

服务员已经替换灰盒块，并继续执行：

前往脏桌 → 收盘 → 擦桌 → 桌子恢复可用。

收盘和擦桌使用统一动作接口，不再写第二套员工动画逻辑。

### 家具与场景

原有碰撞、NavigationObstacle2D、ServicePoint、RefillPoint、CleanPoint 全部保留。

这意味着本次只是把视觉层替换为正式母版：

- 顾客行为没有重写。
- 厨房生产没有重写。
- 桌位生命周期没有重写。
- 餐台排队没有重写。
- 原料和经济系统没有重写。

### 遮挡深度

人物节点已经使用脚底 Y 坐标更新 z_index。

主要固定家具也按照场景 Y 坐标设置固定 z_index。

因此当前已经具备第一版前后遮挡基础，后续精修主要调整：

- 家具视觉高度
- 脚底锚点
- Sprite 偏移
- 具体遮挡分层

而不是重新设计场景逻辑。

## v0.7 当前验证目标

现在不再看“系统有没有”，而看第一套成品感是否成立：

1. 720×1280 下人物大小是否合适。
2. 3.2～3.8 头身是否比大头 Q 版更符合项目方向。
3. 64×32 斜俯视格与家具比例是否协调。
4. 顾客、厨师、服务员是否能被快速区分。
5. 端盘状态是否清楚。
6. 人物在桌子和餐台前后的遮挡是否自然。
7. 热门餐台排队时是否仍然看得清楚。
8. 3 张双人桌的餐厅是否显得太挤或太空。
9. SVG 母版替换成后续 PNG 时是否无需改代码。

## 已知限制

当前执行环境不能直接启动 Godot，因此已经完成的是：

- 仓库代码接入
- 场景引用检查
- SpriteFrames 资源检查
- 旧灰盒视觉引用清理
- v0.7 静态结构检查

真正的运行时效果、SVG 导入结果和动画节奏仍需要 Godot / Android 真机运行确认。

## 下一阶段：v0.8

v0.8 不继续增加大型系统。

优先做：

1. 真机运行 v0.7。
2. 修正人物大小、脚底锚点、家具遮挡和卡路问题。
3. 确定第一套人物与家具母版是否合格。
4. 如果合格，再扩：
   - 3～5 种顾客外观
   - 第 2 套双人桌
   - 3 个不同外观餐台
   - 第一套正式食物图
5. 之后才进入更大餐厅和扩建系统。

## 项目原则

- 正式素材只能替换视觉层，不允许为了某张图重写经营逻辑。
- 不保留废弃视觉入口。
- AI 批量生图前必须先通过一套母版真机验证。
- UI、人物、家具继续统一按照 720×1280 与斜俯视规范执行。
