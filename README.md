# Buffet Restaurant Sim

Godot 4 自助餐经营模拟项目。当前阶段仍以“餐厅必须真正运行”为优先，正式美术只从垂直切片开始。

## 当前版本：v0.6 垂直切片准备

### 这一版新增

- 厨师从后台计时器升级为可见的场景员工。
- 厨师会：
  - 接厨房任务
  - 去后厨准备
  - 实际制作
  - 端菜走到餐台补货
- 厨房本身只负责任务与原料规则，不再假装“后台自动做菜”。

### 真实取餐队列

每个餐台现在拥有独立队列：

- 顾客先选择目标菜。
- 前往该餐台队尾。
- 热门餐台会真正排队。
- 队列过长会影响顾客耐心。
- 顾客选择餐台时也会考虑排队长度。
- 餐台空盘时，队列会等待厨房补菜。

### 顾客端盘状态

顾客流程现在是：

进店 → 收银排队 → 付款取盘 → 选择餐台 → 餐台排队 → 夹菜 → 端盘找座 → 吃饭 → 再次取餐 / 厕所 / 离店。

灰盒人物已经显示“有盘 / 无盘”状态，为后续正式动画预留接口。

### 多座位餐桌

旧的“一张桌 = 一个顾客”模型已淘汰。

现在使用 BuffetTable：

- 一张桌可以管理多个 SeatPoint。
- 当前为 3 张双人桌，共 6 个座位。
- 两名顾客可以共享同一张双人桌。
- 只有最后一名顾客离桌后，整张桌才变脏。
- 服务员按“整桌”执行收盘与擦桌。

### 服务员动作阶段

清桌不再是一段计时：

前往脏桌 → 收盘 → 擦桌 → 桌子重新开放。

### 补菜经营控制

玩家现在可以：

- 设置厨房优先：自动 / 主食 / 肉类 / 海鲜。
- 单独暂停或恢复：
  - 主食补菜
  - 肉类补菜
  - 海鲜补菜
- 查看每个餐台：
  - 当前库存
  - 排队人数
  - 已消耗实际成本
  - 给顾客提供的主观价值

这已经开始形成“老板赚钱”和“顾客觉得回本”的直接冲突。

### 正式美术规范

新增：

docs/VERTICAL_SLICE_SPEC.md

已锁定第一套正式资产的：

- 720×1280 逻辑基准
- 64×32 斜俯视基础菱形格
- 人物约 3.2～3.8 头身
- 普通人物约 44～50×76～84 逻辑像素
- 四方向斜俯视动画
- 桌子 / 餐台占格规范
- ServicePoint / RefillPoint / CleanPoint
- Y 排序与脚底锚点
- AI 批量素材生成统一规则

## 已删除旧结构

v0.6 完成后不再保留旧 BuffetSeat 单座位实现，统一使用 BuffetTable 多座位模型。

## 下一阶段：v0.7 垂直切片

下一步不继续添加大量经营系统，而是做第一块真正接近成品的内容：

1. 制作 1 套正式普通顾客人物。
2. 制作 1 套正式厨师与服务员。
3. 制作双人桌、餐台、收银台、地板、墙体第一套正式素材。
4. 把灰盒替换成正式斜俯视素材。
5. 验证人物遮挡、Y排序、四方向行走、端盘、夹菜、吃饭、补菜和清桌动画。
6. 真机确认比例后，才开始批量扩素材。

## 项目原则

- 不用新增页面掩盖核心场景不好玩的问题。
- 同类对象统一接口，不复制旧实现。
- 废弃底层直接删除，不长期保留两套入口。
- 正式素材母版通过真机验证后，才批量生产。
