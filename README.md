# Buffet Restaurant Sim

Godot 4 自助餐经营模拟项目。当前仍处于灰盒原型阶段：先验证餐厅生态是否真正好玩，再进入正式斜俯视美术与人物动画。

## 当前版本：v0.4 店铺生态灰盒

### 基础规格

- 720×1280 逻辑基准，9:16
- canvas_items + expand 适配不同竖屏比例
- 1× / 2× / 3× 时间倍率
- Godot 4，当前全部使用灰盒占位资产

### 当前已经跑通的顾客循环

进店 → 收银排队 → 付款 → 自主选择餐台 → 取不同份量 → 找座 → 无座等待 → 吃饭 → 判断是否继续拿菜 → 产生厕所需求 → 厕所排队 → 离店 → 生成评价。

### 顾客系统

- 普通顾客 / 健身顾客 / 大胃王
- 不同胃容量
- 不同单次取餐份量
- 不同菜品偏好
- 不同“想吃回本”的倾向
- 饱食度
- 回本感
- 耐心
- 舒适度
- 厕所需求
- 排队时间
- 最终 1～5 星评价和评价原因

### 自助餐台与厨房

- 主食台 / 烤肉台 / 海鲜台
- 餐台库存按浮点份量计算，不再按“一个人一次吃500g”这种错误方式处理
- 顾客每次夹取量因人而异
- 每种食物分离三个关键数值：
  - 饱腹贡献
  - 顾客主观价值
  - 实际成本
- 厨房会自动寻找低库存餐台
- 厨房需要生产时间
- 分批补菜
- 备餐即产生食材成本
- 另外统计实际被顾客吃掉的食材成本，后续可用于计算浪费

### 座位与厕所

- 6 个座位
- 座位满时顾客进入等座队列，不再直接离店
- 等太久会消耗耐心并提前离店
- 当前 1 个厕所服务位
- 厕所会形成排队
- 厕所等待会消耗耐心并影响评价

### 温度与空调

- 室外温度
- 室内温度
- 顾客数量 + 厨房运行形成真实热负荷
- 空调开关
- 20～28℃设定温度
- 温度偏离舒适区会持续降低顾客舒适度
- 空调产生电费
- 人多时热负荷提高，维持低温的电费也会上升

### 经营数据

当前实时统计：

- 门票收入
- 备餐食材成本
- 已被吃掉的食材成本
- 空调电费
- 当前利润
- 各餐台库存
- 收银队列
- 等座队列
- 厕所队列
- 最新顾客评价

营业结束结算：

- 完成顾客数
- 平均回本感
- 平均星级
- 最终利润

## 当前版本要验证的问题

v0.4 的目的不是“做漂亮”，而是回答这些问题：

1. 餐台缺货是否会真正形成压力。
2. 厨房补菜速度是否会影响顾客选择和评价。
3. 座位数量是否会造成合理的高峰拥堵。
4. 收银、等座、厕所是否会共同消耗顾客耐心。
5. 空调温度与电费是否会形成经营取舍。
6. “顾客觉得回本”和“老板实际赚钱”能否同时成立又互相冲突。
7. 大胃王、健身客和普通顾客是否已经出现明显不同的经营影响。

## 下一阶段：v0.5

下一阶段不继续盲目叠系统，先把灰盒变成更接近真正餐厅模拟的结构：

- 建筑和餐台加入真实碰撞/导航障碍
- 顾客不能穿过桌椅、收银台和餐台
- 餐台改为“服务点 + 实体占格”
- 厨房加入原料库存，而不是无限生产
- 菜品增加真正的采购单位 / 制作批次 / 顾客夹取量
- 员工任务队列：厨师补菜、服务员收桌
- 桌面清洁状态
- 顾客离桌后的脏桌占用
- 第一次可玩的“经营决策”：玩家主动控制补菜优先级和空调策略

## 项目原则

- 先验证玩法，再做正式美术。
- 同类对象使用统一接口，不给每道菜单独复制代码。
- UI 负责观察和控制模拟世界，不能用 UI 假装餐厅在运行。
- 原型阶段允许重构；垂直切片通过后再逐步冻结底层接口。
- 正式人物、桌椅、餐台批量生产之前，必须先锁定斜俯视角度、人物比例、占格和动画母版。
