# Buffet Restaurant Sim

Godot 4 自助餐经营模拟项目。当前仍然坚持“先把餐厅真正跑起来，再做正式斜俯视美术”。

## 当前版本：v0.5 场景运行基础

### 已完成：真正的场景实体

- 720×1280 竖屏逻辑基准
- 收银台、后厨、厕所、餐台、桌位加入 StaticBody2D 物理碰撞
- 12 处主要家具/设施加入 NavigationObstacle2D 避障
- 顾客与服务员不能再直接穿过桌椅、餐台和功能区
- 餐台拆分为“实体家具 + ServicePoint 取餐点”
- 桌位拆分为“实体桌位 + ServicePoint 就座/清洁点”
- 顾客不再把家具中心当成移动目标

Godot 的导航系统只把导航网格用于寻路，普通视觉和碰撞不会自动改变寻路结果，所以当前灰盒同时使用物理碰撞和 NavigationObstacle2D 的局部避障约束；后续自由装修阶段会进一步做动态导航区域重建。

### 原料仓库

不再允许厨房无限生成菜品。

当前开局原料：

- 主食原料 70 单位
- 肉类原料 42 单位
- 海鲜原料 30 单位

现在链路是：

采购原料库存 → 厨房消耗原料 → 制作一批食物 → 补到餐台 → 顾客按个人份量夹取。

餐台分别记录：

- 对应原料
- 每 1 单位成品需要多少原料
- 餐台容量
- 当前库存
- 饱腹贡献
- 顾客主观价值
- 实际成本

### 厨房生产

- 自动发现低库存餐台
- 一次只执行一个制作任务
- 制作需要时间
- 原料不足时无法继续制作
- 玩家可以设置补菜优先级：
  - 自动
  - 主食
  - 肉类
  - 海鲜

这已经产生第一个真实经营决策：玩家可以为了利润和顾客“回本感”改变厨房产能投向。

### 桌位生命周期

桌位不再只有“有人 / 没人”。

现在状态是：

干净空桌 → 顾客占用 → 顾客离店 → 脏桌 → 服务员接任务 → 走到桌边 → 清桌 → 再次可用。

脏桌期间不能分配给新顾客，因此服务员效率会真实影响翻台率和等座队列。

### 服务员任务队列

已经加入一个灰盒服务员：

- 自动接收脏桌任务
- 多张脏桌进入任务队列
- 服务员实际走到桌边
- 清洁需要时间
- 清洁完成后桌位重新开放

员工现在开始成为场景中的实际单位，而不是 UI 上的“效率 +10%”。

### 已保留并联动的系统

- 顾客饱食度
- 回本感
- 顾客耐心
- 舒适度
- 收银排队
- 等座
- 厕所需求与排队
- 室内外温度
- 顾客 / 厨房热负荷
- 空调和电费
- 1× / 2× / 3× 时间倍率
- 主食 / 烤肉 / 海鲜差异
- 顾客最终星级与文字评价

## 当前重点验证

v0.5 主要验证：

1. 顾客是否还能稳定完成整套行动链，而不会穿过家具。
2. 服务点设计是否让人物停靠位置自然。
3. 脏桌是否开始影响翻台率。
4. 一个服务员是否会在高峰期形成真实瓶颈。
5. 有限原料是否让某类餐台真的会断货。
6. 玩家调整厨房补菜优先级是否会改变利润与回本感。
7. 场景复杂度增加后，多顾客避障是否仍然稳定。

## 下一阶段：v0.6

v0.6 不立即批量做正式素材，而是先做第一个“垂直切片准备”：

- 把厨师从后台计时器升级为可见员工任务单位
- 服务员增加收盘 / 清桌两个动作阶段
- 桌位升级为桌 + 多座位，而不是一桌只等于一个顾客
- 顾客加入端盘状态
- 每个餐台增加排队点，热门菜会形成取餐队列
- 增加第一套小型经营控制：
  - 手动暂停某餐台补菜
  - 调整补菜优先级
  - 查看各餐台成本 / 回本贡献
- 确认斜俯视角度、格子尺寸、人物高度、桌椅占格
- 然后只制作 1 套正式人物和 1 套正式家具做垂直切片

## 项目原则

- 玩法原型通过前，不批量生产美术。
- 家具必须有实体占格和服务点。
- 顾客、员工和设施都通过统一接口交互。
- 不为每一种菜、每一种桌椅复制一套代码。
- 正式美术母版确认后，才让 AI 批量扩人物和家具。
